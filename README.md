# OBD Widget — виджет параметра OBD-II (ELM327)

Виджет рабочего стола для Android 4.4+ (minSdk 19), который подключается к
адаптеру ELM327 по классическому Bluetooth (SPP) и показывает 
значения OBD-II. По умолчанию — температура охлаждающей жидкости (PID 0105).

## Сборка

```bat
set JAVA_HOME=C:\Program Files\Android\Android Studio\jbr
set ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk
gradlew.bat assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

Если `gradlew` не может скачать дистрибутив Gradle, используйте локальный:

```bat
"%USERPROFILE%\.gradle\wrapper\dists\gradle-8.11.1-all\2qik7nd48slq1ooc2496ixf4i\gradle-8.11.1\bin\gradle.bat" assembleDebug
```

## Настройка

1. Спарьте ELM327 в системных настройках Bluetooth (PIN обычно `1234` или `0000`).
2. Откройте приложение «OBD Widget».
3. Выберите параметр, интервал обновления и адаптер (или «Автоопределение»).
4. «Сохранить», затем добавьте виджет на рабочий стол.

## Диагностика

Экран настроек содержит раздел **Diagnostics** с журналом, в который пишется
каждый шаг: список спаренных устройств, все попытки подключения по каждой
стратегии RFCOMM, каждая AT-команда с сырым ответом адаптера и результат
чтения PID.

Кнопки:

* **Самотест** (Run self-test) — полный проход: окружение → сопряжение →
  4 стратегии подключения → `ATZ`, `ATI`, `AT@1`, `ATDPN`, `ATRV`, `ATSP0` →
  `0100`, `0101` → чтение выбранного PID. В конце — строка `RESULT:`.
* **Копировать** — весь журнал в буфер обмена (удобно переслать разработчику).
* **Очистить** — сброс журнала.

Те же строки дублируются в logcat с тегом `ObdDiag`:

```bat
adb logcat -s ObdDiag
```

### Как читать журнал

| Строка | Значение |
|---|---|
| `findAdapter: N paired device(s)` | сколько устройств сопряжено |
| `connect: strategy 1 'SPP secure' SUCCESS` | какая стратегия сработала |
| `connect: strategy 1 FAILED after … ms: …` | текст ошибки Bluetooth |
| `ATI -> "ELM327 v1.5"` | адаптер отвечает, порт живой |
| `ATI -> ""` | порт открыт, но адаптер молчит |
| `01XX payload 7B` | валидный ответ, байты получены |
| `RESULT: … = 83 °C` | сквозной успех |

Типичные причины отказа:

* **`ABORT: all connection strategies failed`** — адаптер занят другим
  телефоном, не подан на разъём OBD-II, или сопряжён, но «подключён» в
  системных настройках (отключите профиль/забудьте устройство и спарьте заново).
* **`ATI -> ""`** — выбран не тот Bluetooth-прибор либо адаптер в режиме BLE.
* **`PID 0105 gave no payload`** — зажигание выключено или автомобиль не
  поддерживает PID; проверьте `0100` в журнале.

## Несколько параметров на виджете

Параметры выбираются **флажками** — можно отметить любое количество. Виджет
показывает их списком «подпись слева, значение справа».

Размер подстраивается сам:

* строк показывается столько, сколько выбрано, но не больше 6 и не больше, чем
  влезает в текущую высоту виджета (≈16 dp на строку);
* шрифт значения = `(высота − 14 dp) / строк × 0.62`, в пределах 9…44 sp —
  одиночное значение читается как прибор, шесть строк — как таблица;
* подписи и строка состояния масштабируются пропорционально;
* если отметить больше параметров, чем влезает, остаток показывается как `+N` в
  нижней строке;
* при изменении размера виджета (`onAppWidgetOptionsChanged`) всё
  пересчитывается и перерисовывается.

## Индикация свежести

Большое число меняет яркость, поэтому замороженное значение не спутать с живым:

| Состояние | Яркость | Что видно |
|---|---|---|
| Идёт опрос | 0.55 | число тускнеет на время чтения |
| Успешное чтение | 1.00 | полная яркость |
| Нет связи < 15 с | 1.00 | «Нет связи · 8 с» |
| 15 с – 1 мин | 0.85 | «Нет связи · 40 с» |
| 1–5 мин | 0.65 | «Нет связи · 3 мин» |
| 5–30 мин | 0.45 | «Нет связи · 12 мин» |
| 30 мин – 2 ч | 0.30 | «Нет связи · 45 мин» |
| больше 2 ч | 0.22 | «Нет связи · 3 ч» |

Последнее удачное значение и его метка времени хранятся в настройках, поэтому
виджет остаётся осмысленным и после перезапуска процесса и перезагрузки.

При повторяющихся ошибках связи интервал опроса плавно растёт (5 с → 30 с
максимум), чтобы уехавший адаптер не разряжал батарею; после успешного чтения
интервал возвращается к заданному в настройках.

## Топливо за поездку (оценка)

В списке параметров есть **Trip fuel used**. Прямого измерения расхода у 
HONDA  нет: сканер ЭБУ показал, что PID `0105`… есть, а `015E` (fuel rate),
`012F` (fuel level) и `0110` (MAF) автомобиль не отдаёт. Поэтому расход
считается моделью, как это делают HobDrive и подобные программы при
неизвестных заводских PID:

* если ЭБУ всё-таки отдаёт MAF (PID 10):
  `л/ч = MAF[г/с] / 14.7 / 745 · 3600`;
* иначе — по скоростному наполнению (speed-density):
  `m_возд[кг/с] = MAP[Па] · VE · V[л]/1000 · RPM / (120 · 287.05 · T[К])`,
  затем `л/ч = m_возд · 1000 / 14.7 / 745 · 3600`, где `VE = 0.85`.

Накопление идёт по **времени работы двигателя** (PID `011F`):

* при выключении зажигания счётчик не растёт;
* при перезапуске двигателя (время работы уменьшилось) поездка начинается заново;
* один шаг интегрирования ограничен 120 с, чтобы пропавшая связь не добавляла
  «фантомное» топливо.

Виджет показывает израсходованные литры крупно, а текущий расход л/ч — мелкой
строкой под числом.

### Калибровка точности

Модель даёт ±10–20 % без настройки. Проверка на заправке:

1. залейте бак «до полного», сбросьте счётчик поездки;
2. проездите известный маршрут, снова залейте до полного и запомните литры;
3. `Поправка % = фактически залитые литры / показанные литры · 100`;
4. впишите её в поле «Поправка, %» (например, показал 10.0 л, залили 8.5 л →
   поправка 85 %).

Объём двигателя задаётся в поле «Объём, л»: для Step WGN в кузове RP3 это
1.5 л (L15B turbo), поправку для него обычно приходится снижать — при наддуве
реальное наполнение выше модельного.

## Примечания

* Каждое чтение не пересбрасывает адаптер: соединение живёт до 60 секунд и
  переиспользуется между опросами (`Session`).
* На Android 12+ требуется runtime-разрешение `BLUETOOTH_CONNECT`; приложение
  запрашивает его при открытии настроек.
* Интервал опроса — от 2 до 300 секунд, планировщик `AlarmManager`.
